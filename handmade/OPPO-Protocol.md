# OPPO RFCOMM 总结

- **蓝牙信道**: 根据SPP UUID:`0000079A-D102-11E1-9B23-00025B00A5A5`握手

## 数据包结构

```text
AA <TotalLen> 00 00 [Cmd(2字节)] [Seq(1字节)] [PayLen(2字节)] <Payload>
```

> **说明**: `<>` 代表不定长度，`[]` 代表固定长度。

## 字段说明

- **Header**: 固定为 `0xAA`
- **TotalLen (>= 1字节)**: 除Header(`0xAA`)和自身的字节个数。
  - **编码规则**: 
    - 当数值 `< 128` 时，直接用一个字节表示；
    - 当数值 `>= 128` 时，先将该数减1，再按标准LEB128编码（小端序，每字节低7位存放数据，最高位作为是否继续的标志）。
  - **解码规则**: 
    - 若首字节最高位为0，该字节值即为最终结果；
    - 若最高位为1，则继续读取后续字节直到最高位为0，将所有字节的低7位按小端序拼接成整数，再加1还原为原值。
- **Reserved**: 固定为 `0x0000`
- **Cmd (2字节)**: 命令识别码（小端序，Low Byte 在前）
- **Seq (1字节)**: 序列号（当值为 `0xFF` 时代表耳机主动广播）
- **PayLen (2字节)**: Payload长度（小端序，Low Byte 在前）
- **Payload (>= 1字节)**: 负载数据

## 初始化过程

### 1. 初始握手
- **发送数据**: `aa0700000001000000`
- **期望答复**: 收到 `Cmd` (命令识别码) 为 `0x8100` 的答复。
  - *示例*: `aa100000008100090000ff775aeae70ea007`

### 2. 请求广播码列表
- **发送数据**: 若握手成功，发送 `aa0700000002010000`
- **期望答复**: 收到 `Cmd` (命令识别码) 为 `0x8200` 的答复。
  - *示例*: `aa12000082010b00000901020304080bf1f2f3`
- **解析**: 其中 `0x09` 为广播数量，表示有9个广播码，分别为 `0x01, 0x02, 0x03, 0x04, 0x08, 0x0b, 0xf1, 0xf2, 0xf3`

**已知广播码对照表**：
- `0x01` : 电量主动广播
- `0x02` : 佩戴状态主动广播
- `0x03` : 降噪模式主动广播
- `0xf?` : JSON相关debug信息

### 3. 发送广播码
- **发送数据**: 若收到广播码列表，可选择发送 `Cmd` (命令识别码) 为 `0x0205` 的广播码。
  - *示例*: `aa1100000502020a000901020304080bf1f2f3`
- **期望答复**: 收到 `Cmd` (命令识别码) 为 `0x8205` 的答复。
  - *示例*: `aa1b000005820214000109010002000300040008000b00f100f200f302`
- **解析**: 其中 `0x01` 未知， `0x09` 为广播数量，表示有9个广播码，分别为 `0x01, 0x02, 0x03, 0x04, 0x08, 0x0b, 0xf1, 0xf2, 0xf3`，广播码后一字节则代表开启状态， `0x00` 代表正常，但 `0x02` 则代表不存在该广播类别
